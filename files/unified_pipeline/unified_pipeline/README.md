# Unified Multi-Dataset Documentation-Generation Pipeline

Dataset-agnostic framework: every Java dataset is normalized to a single
`DocPair(code_unit, reference_doc)` record, then generated by multiple LLMs and
scored by one shared metric suite, so results are comparable **across datasets**.

## Layout
```
config.py            paths, models, datasets, metrics, sampling  (edit me first)
schema.py            DocPair — the common representation
loaders/             one adapter per dataset -> DocPair
generation/          unified LLM clients + prompt variants + runner
evaluation/          metric suite + per-row eval + cross-dataset aggregation
ira/                 stratified sampling, rater template, agreement stats
run_pipeline.py      orchestrator
```

## Setup
```bash
pip install -r requirements.txt
cp .env.example .env          # add GROQ_API_KEY / HF_TOKEN / GEMINI_API_KEY ...
```
Put each dataset's raw files where `config.DATASETS[...]["raw"]` points
(default: `data/raw/<dataset>/`). `data/raw/train_complete.jsonl` = Lin et al.

## Run
```bash
# full cross-dataset run
python run_pipeline.py --stage load generate evaluate aggregate

# prompt-engineering study (EXP-004), one dataset, all 5 variants
python run_pipeline.py --stage prompt --dataset code_review
python run_pipeline.py --stage evaluate aggregate

# inter-rater agreement (stratified 25 across datasets, one model)
python run_pipeline.py --stage ira --one-model groq
# ...both raters fill data/results/ira_eval_template.xlsx, then:
python ira/compute_ira.py
```

## What needs YOUR confirmation
Each loader except `code_review` has the normalization logic done but the
dataset-specific FIELD NAMES marked `CONFIRM` — open the dataset, check the real
column/key names, adjust the `.get(...)` calls. `code_review` already matches
your `extract_doc_pairs.py`.

## Enabling more models (open-source)
All extra models are open-weight and run through the HuggingFace serverless
Inference API with your existing `HF_TOKEN` — no extra account needed. In
`config.MODELS`, flip `enabled: True` for any of: `starchat`, `llama2`,
`magicoder`, `codellama`, `codegen` (base → `hf_text`), `qwen_coder`.
`deepseek` uses DeepSeek's OpenAI-compatible API — set `DEEPSEEK_API_KEY`.

Notes:
- Some HF models are gated (Llama 2, CodeLlama) — accept the license on the
  model's HF page first, or the call returns an auth error.
- `codegen` is a base completion model, so it routes through `hf_text`
  (text_generation) instead of chat. Output may need light cleanup.
- `pangu_coder` (Huawei) is not openly hosted on HF; leave it disabled until you
  have an accessible endpoint, then set its `model`/`provider`.
